# SAVEUR — бронирование столика

**Демонстрация (Vercel):** [ссылка](#)

Пет-проект — страница, где можно забронировать столик в ресторане: заполняешь форму и получаешь подтверждение.

## Стек

React, Next.js (Pages Router), TypeScript, CSS Modules.

## Как запустить

```bash
npm install
npm run dev
```

Открыть [http://localhost:3000](http://localhost:3000).

Ещё команды:

```bash
npm run build   # собрать проект
npm run start   # запустить собранную версию
npm run lint    # проверить код линтером
npm run test    # прогнать тесты
```

## Почему сделано именно так

- Взял Pages Router, а не App Router — страница одна и простая, не хотелось тащить лишнюю инфраструктуру.
- Все проверки полей (имя, телефон, дата и т.д.) вынес в отдельный файл `validation.ts` — так их удобно тестировать отдельно от формы.
- Состояние (обычная форма / грузится / готово) держу на уровне страницы, а не внутри самой формы — так форма и экран подтверждения не завязаны друг на друга напрямую.
- Стили — обычные CSS Modules, без Tailwind и SCSS: для одной страницы этого более чем достаточно.
- Проверку телефона написал сам, а не взял один в один из примера в задании — по смыслу то же самое (11 цифр, начинается на 7 или 8), но своими словами.
- Имя автоматически приводится к нормальному виду («Иван Иванов»), когда пользователь уходит из поля — специально не на каждую букву, чтобы не мешать печатать.

## Что можно было бы доделать

**Разложить проект по-другому.** Сейчас всё лежит по типам файлов: отдельно компоненты, отдельно утилиты, отдельно типы. Если бы проект рос дальше, я бы, наверное, сгруппировал всё по фичам — чтобы каждая часть приложения (например, форма бронирования) лежала в своей папке, а внутри неё отдельно разметка и отдельно логика. Примерно так:

```
booking-form/
  BookingForm.tsx        — сама разметка
  useBookingForm.ts      — весь стейт и обработчики
  validation.ts
  types.ts
```

Тогда компонент занимался бы только версткой, а весь стейт, обработчики и эффекты жили бы в отдельном хуке — и то, и другое проще читать по отдельности.

**Убирать прошедшее время из списка.** Сейчас можно выбрать слот 12:00, даже если на часах уже 14:00 — список времени не смотрит на текущее время. Хотелось бы это поправить примерно так:

```ts
function getAvailableTimeSlots(date: string, slots: string[]): string[] {
  const isToday = date === todayISODate();
  if (!isToday) return slots;

  const now = new Date();
  const currentMinutes = now.getHours() * 60 + now.getMinutes();

  return slots.filter((slot) => {
    const [hours, minutes] = slot.split(':').map(Number);
    return hours * 60 + minutes > currentMinutes;
  });
}
```

Если выбрана сегодняшняя дата — просто отфильтровываем часы, которые уже прошли.

**И по мелочи, что можно поправить прямо в этом проекте** (без бэкенда и всего внешнего):

- функция с сегодняшней датой сейчас продублирована в двух файлах — стоит вынести в одно место;
- сделать маску для телефона, чтобы цифры сами вставали как +7 (___) ___-__-__;
- разбить форму на кусочки поменьше — сейчас это один большой компонент;
- сохранять то, что человек уже ввёл, в localStorage, чтобы при случайном обновлении страницы всё не стёрлось;
- добавить что-то для скринридеров — например, чтобы ошибки озвучивались и фокус сам прыгал на первое проблемное поле;
- добавить анимацию при переходе от формы к экрану подтверждения;
- подключить настоящий бэкенд вместо фейковой задержки;
- написать пару end-to-end тестов на весь сценарий бронирования.
